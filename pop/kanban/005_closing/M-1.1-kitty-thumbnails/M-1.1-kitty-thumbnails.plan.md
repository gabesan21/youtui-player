# Plan — [[M-1.1-kitty-thumbnails]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** render search/playlist and "now playing" thumbnails as real images via the Kitty graphics protocol when the terminal supports it, gated by a `[ui] image_mode` config option (`auto|kitty|blocks`), keeping the current pixelated `tview.Image` rendering as automatic fallback.
- **Observable result:** in Kitty the user sees real thumbnails in the list and player box; in any other terminal, inside tmux, or with `image_mode = "blocks"` the app looks and behaves exactly as today.

## Strategy

Technical basis is the delivered recon [[pop/researches/kitty-thumbnails/kitty-thumbnails|Kitty thumbnails recon]] — follow its decisions; do not re-derive them.

Hand-rolled Kitty protocol subset (transmit file `a=T, t=f` from the existing cache paths, place by cell `c/r`, delete by ID) with **no new dependencies** — available libraries target print-and-exit, not managed placements. Capability detection: `TERM=xterm-kitty`/`KITTY_WINDOW_ID` plus the config toggle; `$TMUX` forces the fallback (no Unicode-placeholder passthrough in this iteration). The image primitive draws **blank cells** so tcell keeps ownership of the area, and emits escapes so they survive tcell's flush (via `SetAfterDrawFunc` or a `tcell.Screen` decorator — the spike picks one empirically). Placements are terminal-stateful: scroll, page change, resize and exit must delete them; the existing stale-thumbnail race on page change is fixed together with stale-placement handling. The thumbnail cache's 100×100 px cap is raised/removed so kitty mode has adequate source resolution.

**Spike gate inside the front:** before scaling to the list, validate flush ordering, z-index-below-text and resize behavior on real Kitty with a minimal primitive on the "now playing" box. Spike failure is an abort (return with evidence), never a silent scope change. The `detailsThumb`/`detailsView` dead code stays untouched (recon decision: ignore; not wired in this task).

## Risks and abort conditions

- **Risk:** escape/flush interplay garbles rendering — mitigation: spike first, blank-cell ownership, delete-all on exit.
- **Risk:** stale placements on page/scroll — mitigation: placement registry deleted on every layout-affecting event; same guard fixes the stale-thumbnail race.
- **Risk:** cache change degrades blocks mode — mitigation: one cap serving both sinks; blocks sink keeps reading the same path.
- **Abort if:** the spike shows escapes cannot survive tcell's flush or z-index overlaps text on real Kitty — set `blocked: true` with spike evidence; return to 002.
- **Abort if:** capability detection proves unreliable in the target environment — same route.
