# Plan — [[M-2.1-kitty-scroll-stale]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** make Kitty thumbnails track list content in every direction: scrolling up leaves placements static/mis-paired, deleting a playlist item leaves the removed video's image on screen. Eliminate the bug class by construction (exact cause is not decidable by reading: `q=2` hides terminal errors).
- **Observable result:** in real Kitty, thumbnails follow the cursor up and down in both lists; deleting/moving items or changing page leaves no ghost images; blocks mode is unchanged; `YOUTUI_KITTY_DEBUG=<path>` logs each Sync's decisions for field diagnosis.

## Strategy

Fix the Kitty placement layer (`internal/ui`), not the widgets around it. Four construction changes plus instrumentation: (1) key sinks by **content** — `prefix:videoID` parsed from the thumbnail URL (`i.ytimg.com/vi/<id>/`), fallback to the track URL — instead of `prefix:index`, so index shifts from delete/move/page change cannot mis-pair placements; (2) when a sink's spec changed, **delete the old placement and place with fresh image/placement ids** — never in-place re-place with the same ids (with `t=f` the terminal re-reads the file; cost is one small escape per image); (3) `renderVisibleItems` bumps a per-list generation, and a bump forces re-place of that list's sinks at the next Sync, so scroll in any direction always re-emits placements at current rects without depending on fetch draws; (4) `YOUTUI_KITTY_DEBUG=<path>` logs per-Sync desired vs live keys, deletes, places and rects. The blocks sink is untouched; wiring in `setup.go`/`app.go` stays minimal; no new dependencies. The content-keying convention goes into `internal/ui/AGENTS.md`.

## Risks and abort conditions

- **Risk:** per-scroll re-place emits a few small escapes per visible image — mitigation: paths, not pixels (`t=f`); traffic is negligible.
- **Risk:** the real terminal quirk is something else (e.g. `a=p` with partial crop ignored) — mitigation: fresh ids on every spec change plus the debug log reveal it on the next user reproduction.
- **Abort if:** implementing the design requires touching the blocks path or adding a dependency — set `blocked: true` with evidence.
