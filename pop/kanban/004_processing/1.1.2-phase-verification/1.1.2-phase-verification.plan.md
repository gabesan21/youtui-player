# Plan — [[1.1.2-phase-verification]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** run the Phase 1.1 verification suite over the DOX tree delivered by 1.1.1 — every `verify: phase` criterion accumulated by 1.1.1, plus `pop_validate` (links, wikilinks, `pop-hash` fail-closed) and a read-check that each contract's claims match the code it covers — and fix what the suite catches inside this task.
- **Observable result:** Phase 1.1 contracts validated and consistent with the tree; defects within reach fixed; defects above reach recorded as proposed modifications in memory; Phase 1.1 status closed on pass.

## Strategy

Single executor, read-heavy. First assemble the **phase checklist** from 1.1.1's memory ledger and its plan archived in Git, then run `python3 pop/scripts/pop_validate.py` (fail-closed on `pop-hash`), then walk each DOX contract against the code it covers by reading. Fixes are limited to DOX contract text (`AGENTS.md` files) — the Epoch 1 gate (root AGENTS.md, "Essential rules") forbids touching project content. A wrong durable contract or code defect is **not fixed here**: it becomes a proposed modification recorded in the task memory (WORKFLOW, "Phase verification"). This is the only task kind where a command run is an `agent` criterion; this plan uses that exception for `pop_validate` and the checklist execution. Delivery route: versioned scope — task worktree + PR to `main` at 004/005, human merge (mention only).

## Risks and abort conditions

- **Risk:** checklist sparse or absent in 1.1.1's memory → phase suite under-covers — mitigation: treat the checklist as binding; if empty, the suite is `pop_validate` + read-check and the gap is recorded in memory.
- **Risk:** a finding demands a code or durable-contract change — mitigation: out of reach; record as proposed modification, do not fix.
- **Abort if:** 1.1.1 ledger missing at 004 entry, or the DOX tree is not on `main` — set `blocked: true` naming the dependency.
