# Plan — [[1.2.2-phase-verification]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** Validate each `pop/skills/` entry created by 1.2.1 (build, fmt/vet/test incl. short vs live, run, local Arch install) against the real `Makefile` and `PKGBUILD` by executing their commands read-only where possible, run the phase checklist accumulated by 1.2.1, and fix what the verification catches.
- **Observable result:** every skill's commands match real targets; the phase suite runs green (or is classified to the human checklist); Phase 1.2 closes as `completed` in [[pop/roadmap/1-organization]] on approval.

## Strategy

This is the Phase 1.2 verification task: tests run here, once (section "Phase verification" of [[WORKFLOW]]). A single executor inspects the skills side by side with `Makefile`/`PKGBUILD`, probes commands in the three classes below, and fixes skill defects in place — the originating task is already closed, so an execution defect revealed here is fixed inside this task. A defect above the phase's reach (wrong durable contract, structurally unmet request) is not fixed: it becomes a proposed modification recorded in memory. Delivery route: versioned scope — task worktree + PR to `main`, merged by the human (strategy-level only).

**Command classification (binding for the executor):**

- **Read-only probes (agent):** `make -n <target>` dry-runs (`build test run fmt vet install-bin clean deps`), `make check-deps`, `make version`, `make help`, `makepkg --printsrcinfo`.
- **Safe local runs (agent) — allowed only in this task kind:** `make build`, `make vet`, `make fmt` (pass = no working-tree diff afterwards), and `make test` (`go test ./...`) when `make check-deps` reports all OK. An environmental failure follows the 004 verification stop rule: reclassify as `verify: user` with `ambiente` in telemetry — never build infrastructure to verify.
- **Human verification (`verify: user`):** `makepkg -si` (installs a package) and launching the TUI (needs a display plus live mpv/yt-dlp) — manual step and expected pass go to the PR's human verification checklist.

## Affected areas

- `pop/skills/` — the entries under verification; only defect fixes land here.

- `pop/roadmap/1-organization.md` — Phase 1.2 status closes at 005 act 3.

## Risks and abort conditions

- **Risk:** a skill cites a nonexistent target or stale step — expected defect class; fixed in place with the fix noted in memory.
- **Risk:** `make test` needs live mpv/yt-dlp — mitigation: gate on `make check-deps`; stop rule applies after the second environmental failure.
- **Abort if:** 1.2.1 ledger is missing at execution → `blocked: true` with the dependency evidence.
