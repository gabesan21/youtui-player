# Plan — [[1.3.2-phase-verification]]

- **Stage:** 002_planning · **Owner:** planner agent

## Objective and expected result

- **Objective:** Verify Phase 1.3 deliverables against code reality, run the accumulated phase checklist, and — only on pass — close Phase 1.3 and Epoch 1 statuses, lifting the imported-project gate.
- **Observable result:** Every note/reference from 1.3.1 is confirmed (or corrected) against the code; the phase checklist shows as executed; `pop/roadmap/1-organization.md`, `pop/ROADMAP.md` and `pop/PROJECT.md` record Phase 1.3/Epoch 1 completed and the gate lifted, so content changes become allowed.

## Strategy

One executor, reading-first. Versioned scope: the task works in its own worktree and delivers via PR to `main` (human merge) — route detail is mechanical, per [[WORKFLOW|WORKFLOW]].

The executor obtains 1.3.1's outputs at execution time — the memory ledger `pop/memory/<YYYY-MM-DD>/1.3.1-decisions-and-references.md` and its plan archived in Git — and enumerates every note in `pop/notes/decisions/` and `pop/notes/references/` produced by it. For each note, every cited `file:line` or git ref is opened and read: the citation must actually support the claim. A wrong or stale citation is fixed **inside this task** (correct the note, keep the claim only if code supports it). A structurally wrong note (claim irreconcilable with code reality, wrong durable premise) is **not** fixed: it becomes a proposed modification in `pop/MODIFICATIONS.md` (created on demand) plus a finding recorded in this task's memory.

Then the phase checklist — every `verify: phase` criterion accumulated by 1.3.1, sourced from its memory ledger and archived plan — is executed exactly once and the result recorded; an empty checklist is recorded as such, not invented. `python3 pop/scripts/pop_validate.py` must pass over the notes and the edited DOX. Status edits (Phase 1.3, Epoch 1, gate lifting) are the **last act**, executed only after criteria 1–3 pass — the epoch never closes over a failed verification.

The imported-project gate lives in AGENTS.md as a conditional rule ("until Epoch 1 is completed") and simply stops applying once the ROADMAP marks the epoch completed; the durable record of the lift goes to `pop/PROJECT.md` (decisions + status). Any residual staleness of the AGENTS.md line is a follow-up, not scope here.

## Affected areas

- `pop/notes/decisions/`, `pop/notes/references/` — correction of citations/claims caught by the check.
- `pop/roadmap/1-organization.md` — Phase 1.3 and Epoch 1 status to `completed`.
- `pop/ROADMAP.md` — Epoch 1 row to `completed`.
- `pop/PROJECT.md` — decisions entry + status recording the gate lift.
- `pop/MODIFICATIONS.md` — only if a structurally wrong note is found (proposed modification).

## Execution fronts

### F01 — verify, run checklist, close the epoch

- **Delivery:** verified notes, executed checklist, closed Phase 1.3/Epoch 1 statuses, gate-lift record.
- **Scope:** everything in Objective; reading code for confirmation, never editing it.
- **Owns:** `pop/notes/decisions/**`, `pop/notes/references/**`, `pop/roadmap/1-organization.md`, `pop/ROADMAP.md`, `pop/PROJECT.md`, `pop/MODIFICATIONS.md`.
- **May read:** 1.3.1 memory ledger and archived plan, all project code cited by the notes, `pop/scripts/pop_validate.py`.
- **Must not edit:** project content (code, Makefile, PKGBUILD, README) — note fixes notwithstanding, the gate lifts only via the status edits of this task; no other roadmap or card.
- **Depends on:** 1.3.1-decisions-and-references (closed).
- **Expected input:** 1.3.1 memory ledger + its plan archived in Git + the notes it produced. Absent or incompatible → report `BLOCKED`; never simulate the notes or the checklist.
- **Criteria:** 1, 2, 3, 4, 5.

## Order and parallelism

1. **Wave 1:** F01 (single front, single executor).
2. **Integration:** orchestrator validates the diff against `owns` (`pop_check_scope.py`) and checks the `agent` criteria.

## Risks and abort conditions

- **Risk:** a note is structurally wrong — impact: a fix would rewrite the durable contract — mitigation: proposed modification + memory finding, criterion 1 still passes on the remaining notes.
- **Risk:** status edits performed before verification passes — mitigation: statuses are the final act, gated on criteria 1–3.
- **Abort if:** the expected input (1.3.1 ledger/plan/notes) is absent — set `blocked: true` with evidence; do not reconstruct 1.3.1's work.
